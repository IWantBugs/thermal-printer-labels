# thermal-printer-labels

Приложение для Windows 10/11 (x64): BOM Excel → этикетки Word 58×40 мм.

## Скачать готовую программу

[Скачать ZIP для Windows 10/11 x64](https://github.com/IWantBugs/thermal-printer-labels/raw/refs/heads/main/distribution/thermal-printer-labels-win-x64.zip) — около 63 МБ. Архив также доступен в каталоге `distribution`: откройте файл на GitHub и нажмите **Download raw file**.

## Запуск

Распакуйте архив и запустите `ThermalPrinterLabels.exe`. Установка .NET и Excel не нужна. Для формирования документа, предпросмотра и печати нужен установленный Microsoft Word. Для Xprinter XP-365B установите его драйвер Windows.

1. Нажмите **Открыть BOM…** и выберите `.xlsx`. Если листов несколько, выберите нужный.
2. Заголовки `Line #`, `Designator`, `PartNumber`, `Quantity`, `Name` определяются независимо от порядка столбцов. В окне сопоставления проверьте все поля: каждый выпадающий список содержит все столбцы листа, включая столбцы без заголовков, с примерами данных. Для BOM, где артикул хранится в `Name`, выберите `Name` для «Парт». Один столбец можно использовать для нескольких полей. При необходимости измените строку заголовков в этом же окне.
3. Выберите, нужно ли поле **Упк, шт**. Если нужно, введите количество компонентов в упаковке для каждой строки в таблице. Поле можно включить или отключить флажком.
4. Проверьте данные. Название изделия берётся из имени файла без конечного `BOM` и разделителя. Его можно изменить. Если оно не помещается, появится запрос сокращения с ограничением числа символов.
5. Нажмите **Сохранить DOCX**, **Предпросмотр в Word** или **Печать с предпросмотром**.

Каждая строка BOM становится одной этикеткой на отдельной странице. Альтернативы из скобок не создают дополнительные этикетки. `Sum` берётся из `Name` и сокращается с `…`, если не помещается. Длинное обозначение сохраняется целиком: до пяти строк на одной этикетке либо несколько этикеток с подтверждением. Остальные данные не обрезаются автоматически: слишком длинное значение нужно исправить в таблице. `Кол-во` — `Quantity`, компонентов на одну плату; множитель партии не применяется.

Документ сохраняется рядом с исходным BOM. Конечное `BOM` в имени заменяется на `ETC`: `RS7_ADP_V1_BOM.xlsx` → `RS7_ADP_V1_ETC.docx`. Если суффикса `BOM` нет, добавляется `_ETC`. Перед заменой существующего файла запрашивается подтверждение. Изменение названия изделия в окне не меняет имя выходного файла. Если выходной файл открыт в Word, закройте его перед повторным сохранением.

## Одна этикетка из выбранной строки

Загрузите BOM и щёлкните нужную строку таблицы. При необходимости заполните «Упк, шт» только для этой строки. Нажмите **Сформировать этикетку из строки**: программа создаст DOCX с одной этикеткой, откроет предпросмотр Word и предложит диалог печати. Остальные строки при этой операции не проверяются; пустые упаковки в них не мешают печати выбранной позиции.

Название изделия берётся из текущего поля «Изделие», номер `Line #` — из выбранной позиции. Для предпросмотра Word используется временный документ; DOCX рядом с BOM при печати одной строки не сохраняется. Для печати проверьте макет и подтвердите открытие диалога печати, затем выберите принтер и количество копий.

## Печать

Откроется предпросмотр Word. Программа сравнивает число страниц с числом позиций BOM. При несовпадении показывает предупреждение и не открывает диалог печати автоматически.

После проверки макета подтвердите открытие диалога печати. Выберите **Xprinter XP-365B**, задайте в свойствах драйвера бумагу **58×40 мм**, масштаб **100%**, одну страницу на лист, без подгонки. Выбор принтера и окончательное подтверждение печати выполняются в Word. Для первой проверки напечатайте одну страницу и проверьте границы таблицы и ориентацию этикетки. Размер страницы DOCX не заменяет настройку бумаги в драйвере.

## Сборка из исходников

Нужен .NET SDK 8. Используется C# / WinForms. Приложение читает XLSX и создаёт DOCX через стандартные ZIP/XML API; Excel Automation не используется. Word подключается через COM только для предпросмотра и печати.

```powershell
dotnet build src/LabelApp/LabelApp.csproj -c Release
dotnet publish src/LabelApp/LabelApp.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -o artifacts/windows-x64
```

Результат: `artifacts/windows-x64/ThermalPrinterLabels.exe`. Автономный EXE включает среду .NET; исходники приложения находятся в `src/LabelApp`, чтение BOM и генерация Word — в `src/LabelCore`.

## Проверки

```powershell
dotnet run --project tests/Smoke -- tests/fixtures/RS7_ADP_V1_BOM.xlsx artifacts/smoke.docx
```

Перед проверкой создайте каталог `artifacts`, если его нет. Проверки используют приложенный образец BOM: импорт пяти позиций, отсутствие дубликата U1, перестановка столбцов, имена файлов, необязательная строка упаковки, размер страницы, разрывы страниц и валидация DOCX по схеме Open XML. Пакет Open XML SDK используется только проверками.

В облачной Linux-среде проверены сборка Windows EXE, импорт и генерация документов. Интерфейс Windows, работа с Word через COM и физическая печать на XP-365B в этой среде не выполнялись и требуют проверки в Windows.
